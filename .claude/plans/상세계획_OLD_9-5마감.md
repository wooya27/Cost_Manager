> 목표: 15일 동안 “많이 공부”가 아니라 **작동하는 기능을 하나씩 완성**해서  
> 비용정산 1차 검수 AX/DX MVP를 만든다.
>
> 원칙: 하루 할 일은 최대 3개. 각 작업은 20~40분.  
> 막히면 완성 기준을 낮춰서 **작동하는 최소 기능**부터 만든다.

## 0. 이 계획의 기준

### AX 코치 운영 원칙

- 오늘 만들 기능을 먼저 정한다.
- 개념은 오늘 기능에 필요한 만큼만 배운다.
- 바로 구현한다.
- 막히면 막힌 지점을 오늘 공부할 개념으로 바꾼다.
- 결과물을 확인한다.
- 내 말로 30초 설명한다.
- 포트폴리오/대회 관점으로 의미를 정리한다.

### 15일 MVP 범위

이번 15일 안에 만드는 것은 **AuditFlow AI MVP**다.

```text
CSV 업로드
→ 데이터 미리보기
→ 데이터 요약
→ 위험 탐지
→ 규정 근거 검색
→ 보완 요청 초안
→ 위험 건 상세 화면
→ 대시보드
→ 결과 다운로드
→ 테스트
→ README
→ 3분 발표
```

- 실제 메일/Slack 발송

이번 목표는 “모든 기술을 넣은 서비스”가 아니라

# Week 1 — CSV 검수기 만들기

## Day 1 — Streamlit 첫 화면 + CSV 업로드

### 오늘의 목표

CSV를 업로드하면 표로 보여주는 Streamlit 화면을 만든다.

### 오늘 할 일 3개

1. `[깔아줌+직접]` 프로젝트 폴더, `requirements.txt`, `app.py`를 만든다.
2. `[직접]` Streamlit 제목과 CSV 업로드 버튼을 만든다.
3. `[직접]` 업로드한 CSV를 `st.dataframe`으로 화면에 보여준다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | 폴더 생성, 가상환경 준비, `requirements.txt` 작성 | `streamlit`, `pandas` 설치 준비 |
| 30분 | `app.py`에 제목/설명/업로드 버튼 작성 | 브라우저에 제목과 버튼 표시 |
| 30분 | `pd.read_csv`와 `st.dataframe` 연결 | 업로드한 CSV 표 출력 |

### 오늘 배우는 개념

- Streamlit: 파이썬 코드로 웹 화면을 빠르게 만드는 도구
- `st.file_uploader`: 파일 업로드 버튼
- `pd.read_csv`: CSV를 표 형태 데이터로 읽는 함수

### 지금은 몰라도 되는 것

- FastAPI
- DB 저장
- Docker
- LLM API

### 완료 기준

- `app.py` 파일이 있다.
- `streamlit run app.py`가 실행된다.
- CSV 업로드 버튼이 보인다.
- 업로드한 CSV 데이터가 표로 보인다.

### 막혔을 때 대처

업로드가 안 되면 `sample_expenses.csv`를 고정 경로로 읽어서 표만 띄운다.

```python
df = pd.read_csv("sample_expenses.csv")
st.dataframe(df)
```

### 30초 설명 문장

“Streamlit으로 비용 신청 CSV를 업로드하면 바로 표로 확인할 수 있는 첫 화면을 만들었습니다.”

### 포트폴리오 의미

이 기능은 모든 AX/DX 프로젝트의 시작점이다.  
현업자가 가진 엑셀/CSV 데이터를 시스템에 넣는 첫 입구를 만든 것이다.

## Day 2 — 데이터 요약

### 오늘의 목표

업로드한 비용 데이터의 규모와 품질을 자동으로 요약한다.

### 오늘 할 일 3개

1. `[직접]` 행/열 개수와 컬럼 목록을 표시한다.
2. `[직접]` 결측치 개수를 표시한다.
3. `[직접]` 총 신청 금액과 카테고리별 합계를 표시한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | `df.shape`, `df.columns` 표시 | 행/열, 컬럼 목록 출력 |
| 30분 | `df.isna().sum()` 표시 | 컬럼별 결측치 개수 출력 |
| 30분 | `amount.sum()`, `groupby` 집계 | 총액과 카테고리별 합계 출력 |

### 오늘 배우는 개념

- `df.shape`: 데이터 크기
- `isna().sum()`: 비어 있는 값 개수
- `groupby().sum()`: 항목별 합계

### 지금은 몰라도 되는 것

- 복잡한 통계 분석
- 시각화 라이브러리
- 데이터베이스 쿼리

### 완료 기준

화면에 아래 정보가 보인다.

- 전체 건수
- 전체 컬럼 수
- 컬럼 목록
- 결측치 개수
- 총 신청 금액
- 카테고리별 신청 금액

### 막혔을 때 대처

`groupby`가 막히면 총액, 행/열, 결측치까지만 완성한다.

### 30초 설명 문장

“업로드된 비용 데이터의 규모, 결측 상태, 총액과 항목별 금액을 자동 요약해 검수 전에 데이터 품질을 확인할 수 있게 했습니다.”

### 포트폴리오 의미

단순 업로드 앱이 아니라, 데이터를 보고 업무 판단에 필요한 기본 정보를 뽑는 분석 기능이 들어간다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|

## Day 9 — 보완 요청 초안 생성 (템플릿 기본 + LLM 보강)

### 오늘의 목표

위험 사유와 규정 근거를 바탕으로 보완 요청 초안을 만든다.
**기본은 템플릿(항상 작동)**, 규정 근거가 있는 건만 **LLM으로 더 자연스러운 초안**을 만들고,
근거가 없거나 호출이 실패하면 **템플릿으로 되돌린다(fallback).**

### 오늘 할 일 3개

1. `[직접]` f-string 공통 템플릿으로 초안을 만든다. (이게 항상 되는 기본값)
2. `[직접]` 위험 유형별 문구를 분기하고, 근거가 없으면 "확인 필요"로 제한한다.
3. `[개념+직접]` 규정 근거가 있는 건만 LLM 호출로 초안을 생성하고, 실패하면 템플릿으로 fallback 한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | 공통 템플릿 + 위험 유형별 문구 분기 작성 | 근거 없이도 템플릿 초안 생성 |
| 30분 | LLM 키 설정 + 호출 함수 연결 (설정은 깔아줌) | 근거를 넣으면 LLM 초안 1건 생성 |
| 30분 | 근거 있으면 LLM, 없거나 실패하면 템플릿 fallback | 두 경로 모두 앱이 안 죽고 동작 |

### 오늘 배우는 개념

- f-string / if-elif 템플릿 (항상 되는 기본값)
- LLM API 호출: 프롬프트에 "위험 사유 + 규정 근거"를 넣어 초안을 받는다
- fallback 설계: 근거 없음 / 호출 실패 시 템플릿으로 안전하게 되돌리기 (= 환각 방지)

### 지금은 몰라도 되는 것

- 프롬프트 자동 평가 / LLM judge
- 스트리밍 출력
- 멀티 에이전트

### 완료 기준

위험 건마다 아래 정보가 생성된다.

- `suggested_action`
- `draft_message`
- 근거 있는 건은 LLM 초안, 근거 없거나 호출 실패 건은 템플릿 초안 (둘 다 앱이 안 죽음)

### 막혔을 때 대처

**핵심 원칙: 템플릿이 먼저 완성되면 오늘은 이미 성공이다.**
LLM 연결이 막히면 오늘은 템플릿까지만 하고, LLM 호출은 Day 15 점검 시간의 남는 시간에 붙인다.
API 키 설정·설치는 학습 대상이 아니라 "깔아주는 부분"이니 막히면 15분 넘기지 말고 바로 물어봐라.

### 30초 설명 문장

“기본은 템플릿으로 안정적으로 초안을 만들고, 규정 근거가 확인된 건만 LLM으로 더 자연스러운 초안을 생성하되, 근거가 없거나 호출이 실패하면 템플릿으로 되돌려 환각을 막도록 설계했습니다.”

### 포트폴리오 의미

반복 커뮤니케이션을 줄이는 AX/DX 기능이자, "AI를 언제 쓰고 언제 막을지"를 정한 근거 기반·fallback 구조를 보여준다.
면접에서 "AI가 어디 있냐"는 질문에 바로 답할 수 있는 지점이다.

# 8. 최종 발표 3분 구조

```text
1. 문제
비용정산 담당자는 매월 반복적으로 영수증 누락, 한도 초과, 중복 신청, 사유 부족 여부를 확인해야 합니다.

2. 해결
AuditFlow AI는 비용 신청 CSV를 업로드하면 7종 위험 후보를 자동 탐지하고, 관련 비용 규정 근거와 보완 요청 초안을 제공합니다.

3. 데모
CSV를 업로드하면 데이터 요약이 나오고, 위험 건 목록과 규정 근거, 초안, 대시보드, 결과 다운로드까지 한 번에 이어집니다.

4. 효과
담당자는 전체 신청 건을 처음부터 모두 보는 대신 위험 후보를 우선 검토할 수 있고, 보완 요청 문구 작성 시간을 줄일 수 있습니다.

5. 한계
MVP에서는 실제 OCR, ERP 연동, DB 저장, 실제 메일 발송은 제외했습니다. LLM은 규정 근거가 확인된 건에만 초안 생성 용도로 제한 사용하고, 근거가 없거나 호출이 실패하면 템플릿으로 fallback 해 환각을 막았습니다. v1에서는 DB 저장과 검수 이력 관리, v2에서는 FastAPI와 pgVector 기반 RAG로 확장할 계획입니다.
```
