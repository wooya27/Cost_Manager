## 1. 채용공고 기술스택을 AuditFlow AI에 연결하는 방식

| 채용공고 요구 | AuditFlow AI에서 보여줄 증거 |
|---|---|
| 고객 요청 사항 분석을 통한 LLM/RAG 활용 시나리오 발굴 | 비용정산 담당자의 반복 검수 업무를 LLM/RAG 적용 시나리오로 정의 |
| 자사 솔루션 기반 AI 에이전트 개발/유지보수 | Streamlit 기반 비용정산 검수 어시스턴트 MVP 구현 |
| 검증된 방법론을 공동 자산으로 발전 | 규칙, 규정 검색, 초안 생성, 로그 구조를 모듈화 |
| LangGraph 기반 AI 에이전트 구현 | 위험 건 1개 처리 흐름을 LangGraph 노드로 구성 |
| Langfuse 모니터링/튜닝 | LLM 초안 생성 입력/출력/실패/fallback 로그 기록 |
| Multi AI Agent 아키텍처 | Rule Agent, Policy Agent, Draft Agent, Review Agent 역할 분리 |
| 새로운 도메인 빠른 파악 | 비용정산 업무 규칙을 데이터 컬럼과 정책 문서로 구조화 |
| 구체적이지 않은 문제의 기술적 정의 | “1차 검수 자동화”라는 MVP 범위로 문제를 좁힘 |
| 고객 요구 기반 최적 AI 솔루션 설계 | LLM을 모든 곳에 쓰지 않고, 근거 있는 초안 생성에만 제한 사용 |

# Week 1 마무리 — Rule Agent 재료 완성

## Day 5 — 중복/이상 비용 탐지 + Week 1 마무리

### 오늘의 목표

중복 신청과 이상 비용 후보까지 탐지해 7종 위험 탐지를 완성한다.

### 오늘 할 일 3개

1. `[직접]` 중복 신청 의심 건을 찾는다.
2. `[직접]` 카테고리 평균의 2배 이상인 이상 비용 후보를 찾는다.
3. `[복습]` Week 1 전체 흐름을 실행하고 30초 설명한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | `duplicated`로 중복 탐지 | 동일 직원/날짜/금액/사용처 중복 표시 |
| 40분 | 카테고리 평균 대비 이상 비용 탐지 | 평균 2배 이상 후보 표시 |
| 30분 | 업로드→요약→위험 탐지 전체 실행 | Week 1 데모 성공 |

### 오늘 배우는 개념

- `duplicated(subset=...)`: 중복 행 찾기
- `groupby().transform("mean")`: 그룹 평균을 각 행에 붙이기
- 위험 우선순위: 어떤 건을 먼저 봐야 하는가

### 완료 기준

7종 위험 유형이 작동한다.

```text
[ ] 영수증 누락
[ ] 식대 한도 초과
[ ] 야근식대 한도 초과
[ ] 택시비 사유 부족
[ ] 사무용품 추가 승인 필요
[ ] 중복 신청 의심
[ ] 이상 비용 후보
```

### 막혔을 때 대처

이상 비용 후보가 어렵다면 중복 신청까지만 완성해도 Day5 성공으로 본다.

### 30초 설명 문장

“비용정산 데이터에서 영수증, 한도, 사유, 중복, 이상치 기준으로 7종 위험 후보를 자동 탐지하는 1차 검수기를 만들었습니다.”

### 채용공고 어필 문장

“비용정산 도메인의 반복 검수 기준을 Rule Agent로 구조화해, 사람이 먼저 봐야 할 위험 후보를 자동 선별하도록 만들었습니다.”

# Week 2 — RAG와 LLM 초안 만들기

## Day 6 — 비용 규정 문서 작성 + 문단 분리

### 오늘의 목표

비용 규정 문서 `policy.txt`를 만들고, 문단 단위로 나눈다.

### 오늘 할 일 3개

1. `[직접]` `policy.txt`에 비용 규정 샘플을 작성한다.
2. `[개념+직접]` 문서를 섹션 단위로 나눈다.
3. `[직접]` 문단 리스트를 화면에서 확인한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | 영수증/식대/택시/중복 규정 작성 | `policy.txt` 생성 |
| 30분 | `open().read()`와 `split` 사용 | 문단 리스트 생성 |
| 30분 | Streamlit 또는 print로 문단 확인 | 규정 조각 확인 가능 |

### 오늘 배우는 개념

- 파일 읽기
- 문자열 나누기
- chunk: 문서를 검색하기 쉽게 나눈 조각

### 완료 기준

- `policy.txt` 파일이 있다.
- 정책 문서가 여러 문단으로 분리된다.
- 각 문단에 제목과 내용이 있다.

### 막혔을 때 대처

자동 split이 어렵다면 파이썬 리스트로 규정 조각을 손으로 만든다.

### 30초 설명 문장

“비용 규정 문서를 조각으로 나눠 위험 건에 맞는 근거를 찾을 수 있게 준비했습니다.”

### 채용공고 어필 문장

“업무 문서를 RAG에 활용하기 위해 정책 문서를 문단 단위 chunk로 나눠 검색 가능한 형태로 만들었습니다.”

### 오늘의 목표

위험 유형에 맞는 규정 문단을 찾아 반환하는 검색 함수를 만든다.

### 오늘 할 일 3개

1. `[직접]` 위험 유형과 검색 키워드 매핑표를 만든다.
2. `[직접]` 관련 규정 문단을 찾는 함수를 만든다.
3. `[복습]` 근거가 없을 때 “관련 규정 확인 필요”를 반환한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | `risk_type → keyword` dict 작성 | 매핑표 완성 |
| 40분 | `find_policy_evidence()` 함수 작성 | 위험 유형별 근거 반환 |
| 30분 | 실패 케이스 기본값 처리 | 근거 없으면 확인 필요 표시 |

### 오늘 배우는 개념

- dict 매핑
- 문자열 포함 검색
- 실패 케이스 기본값 처리

### 완료 기준

- `src/policy_retriever.py` 파일이 있다.
- 위험 유형을 넣으면 관련 규정 문단이 나온다.
- 못 찾으면 임의로 만들지 않고 “관련 규정 확인 필요”가 나온다.

### 막혔을 때 대처

모든 위험 유형을 연결하지 말고, 영수증/식대/택시 3개만 먼저 연결한다.

### 30초 설명 문장

“위험 유형에 맞는 비용 규정 문단을 검색해 검수 결과에 판단 근거를 함께 제공하도록 만들었습니다.”

### 채용공고 어필 문장

“비용 규정 문서를 검색 대상으로 삼아 위험 판단에 대한 근거를 제공하는 미니 RAG 구조를 구현했습니다.”

## Day 8 — 위험 결과와 규정 근거 결합

### 오늘의 목표

위험 건 테이블에 규정 근거 컬럼을 붙이고 화면에 보여준다.

### 오늘 할 일 3개

1. `[직접]` 위험 건마다 `policy_evidence` 컬럼을 추가한다.
2. `[직접]` 근거 매칭 실패 건을 확인하고 매핑을 보강한다.
3. `[직접]` 화면에 위험 사유와 규정 근거를 함께 표시한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | `apply` 또는 for문으로 근거 추가 | `policy_evidence` 컬럼 생성 |
| 30분 | 근거 없는 건 확인 | 실패 케이스 목록 파악 |
| 40분 | Streamlit 표 출력 정리 | 위험 유형/사유/근거가 한 화면에 표시 |

### 오늘 배우는 개념

- DataFrame에 새 컬럼 추가
- `apply` 또는 for문
- 검색 결과 품질 확인

### 완료 기준

- 위험 건 표에 `policy_evidence`가 보인다.

## Day 13 — LangGraph 미니 적용

### 오늘의 목표

2. `[직접]` 위험 건 1개를 처리하는 node 3개를 만든다.
3. `[직접]` `graph.invoke()` 또는 대체 함수로 결과 1건을 확인한다.

### 30분 단위 실행표

| 시간 | 작업 | 완료 기준 |
|---|---|---|
| 30분 | state 구조 정하기 | `risk_type`, `risk_reason`, `policy_evidence`, `draft_message` 포함 |
| 40분 | node 함수 3개 작성 | detect/retrieve/generate 단계 분리 |
| 40분 | 1건 실행 확인 | 입력 1건 → 근거/초안 결과 반환 |

### 오늘 배우는 개념

- State: 노드 사이에 전달되는 작업 상태
- Node: 한 단계 작업 함수
- Graph: 작업 순서를 연결한 흐름

### 최소 구현 구조

```python
# src/agent_workflow.py

def detect_risk_node(state):
    # 이미 탐지된 risk_type/risk_reason을 그대로 받거나 보강한다.
    return state

def retrieve_policy_node(state):
    # risk_type으로 policy_evidence를 찾는다.
    return state

def generate_draft_node(state):
    # policy_evidence가 있으면 초안을 만든다.
    return state

def run_audit_workflow(state):
    state = detect_risk_node(state)
    state = retrieve_policy_node(state)
    state = generate_draft_node(state)
    return state
```

LangGraph 설치와 문법이 바로 되면 실제 `StateGraph`로 바꾼다.  
설치가 막히면 위 Python 함수형 workflow로 먼저 완성한다.

### 완료 기준

- `src/agent_workflow.py` 파일이 있다.
- 위험 건 1개가 workflow를 통과한다.
- 결과에 `policy_evidence`와 `draft_message`가 붙는다.

### 막혔을 때 대처

LangGraph 라이브러리 사용이 30분 이상 막히면 Python 함수형 workflow로 대체한다.  
오늘의 핵심은 라이브러리 암기가 아니라 **Agent 흐름을 분리하는 것**이다.

### 30초 설명 문장

“기존에는 함수 호출 순서로 처리하던 검수 흐름을 LangGraph 스타일의 노드 구조로 분리해, 위험 탐지·규정 검색·초안 생성을 단계별로 추적 가능한 에이전트 워크플로우로 구성했습니다.”

### 채용공고 어필 문장

import json
from datetime import datetime
from pathlib import Path

LOG_PATH = Path("logs/llm_calls.jsonl")

def log_llm_call(record: dict):
    LOG_PATH.parent.mkdir(exist_ok=True)

    record["timestamp"] = datetime.now().isoformat(timespec="seconds")

# 7. README/면접용 핵심 문장

## 프로젝트 한 줄 소개

```text
AuditFlow AI는 비용정산 CSV와 사내 규정 문서를 기반으로 위험 신청 건을 탐지하고, 규정 근거와 보완 요청 초안을 제공하는 AX/DX 업무 검수 어시스턴트입니다.
```

## 기술 선택 이유

```text
Python과 Pandas는 비용정산 데이터를 빠르게 분석하고 규칙 기반 검수를 구현하기 위해 사용했습니다.
Streamlit은 담당자가 직접 업로드, 검수, 다운로드할 수 있는 화면을 빠르게 만들기 위해 사용했습니다.
RAG 구조는 위험 판단의 근거를 사내 규정 문서에서 찾기 위해 적용했습니다.
LLM은 규정 근거가 있는 건에 한해 보완 요청 초안을 생성하는 용도로 제한 사용했습니다.
LangGraph는 위험 탐지, 규정 검색, 초안 생성을 노드 단위로 분리해 Agent workflow로 확장하기 위해 반영했습니다.
Langfuse 또는 로컬 로그는 LLM 호출 결과와 fallback 여부를 추적해 프롬프트 개선과 품질 관리를 할 수 있게 하기 위해 반영했습니다.
```

## Agent 구조 설명

```text
AuditRuleAgent는 비용 신청 데이터에서 위험 후보를 탐지합니다.
PolicySearchAgent는 위험 유형에 맞는 사내 규정 근거를 찾습니다.
DraftMessageAgent는 근거를 바탕으로 보완 요청 초안을 생성합니다.
ReviewSupportAgent는 담당자가 위험 건을 검토하고 상태를 관리할 수 있게 돕습니다.
```

## 안전 설계 설명

```text
LLM은 모든 건에 무조건 사용하지 않았습니다.
규정 근거가 있는 건에만 LLM 초안 생성을 허용했고,
근거가 없거나 LLM 호출이 실패하면 템플릿 초안으로 fallback하도록 설계했습니다.
이를 통해 환각 가능성을 줄이고, 담당자가 검토 가능한 형태로 결과를 제공했습니다.
```

# 9. 최종 발표 3분 구조

```text
1. 문제
비용정산 담당자는 매월 반복적으로 영수증 누락, 한도 초과, 중복 신청, 사유 부족 여부를 확인해야 합니다.
이 과정은 시간이 많이 들고 담당자마다 판단 기준이 달라질 수 있습니다.

2. 해결
AuditFlow AI는 비용 신청 CSV를 업로드하면 7종 위험 후보를 자동 탐지하고,
관련 비용 규정 근거와 보완 요청 초안을 제공합니다.

3. 기술 구조
Rule Agent는 비용 데이터에서 위험 후보를 탐지합니다.
PolicySearchAgent는 비용 규정 문서에서 관련 근거를 찾습니다.
DraftMessageAgent는 규정 근거가 있는 건에 한해 LLM으로 보완 요청 초안을 생성합니다.
ReviewSupportAgent는 담당자가 사유, 근거, 초안, 검수 상태를 확인하도록 돕습니다.

4. 데모
CSV를 업로드하면 데이터 요약이 나오고,
위험 건 목록과 규정 근거, 초안, 대시보드, 결과 다운로드까지 한 번에 이어집니다.

5. 효과
담당자는 전체 신청 건을 처음부터 모두 보는 대신 위험 후보를 우선 검토할 수 있고,
보완 요청 문구 작성 시간을 줄일 수 있습니다.
또한 근거와 로그를 함께 남겨 검수 품질을 개선할 수 있습니다.

6. 한계와 확장
MVP에서는 실제 OCR, ERP 연동, DB 저장, 실제 메일 발송은 제외했습니다.
LangGraph와 Langfuse는 우선 1건 workflow와 로컬 로그 중심으로 작게 반영했습니다.
v1에서는 PostgreSQL과 FastAPI로 검수 이력을 저장하고,
v2에서는 pgVector 기반 RAG와 Langfuse 모니터링을 고도화할 계획입니다.
```
