## 0. 이 계획을 짠 원칙 (AX 코치 + ADHD 규칙 반영)

- **공부 = 작동하는 기능 하나 만들기.** 이론 먼저 파지 않는다.
- 하루 **세션 4개**, 각 **25~40분**. 한 번에 이만큼만 본다.
- 기술은 그 기능에 **필요한 만큼만**, 우선순위 순서대로 (Python·Pandas·Streamlit → LLM → RAG → SQL → …).
- 매 세션은 태그가 붙어 있다:
  - `[직접]` = **학습 대상. 내가 직접 코드를 쓴다.** (코치는 힌트 단계로만 돕는다)
  - `[개념]` = 그 기능에 필요한 최소 개념을 코치가 먼저 짧게 떠먹여준다 (예시 1~2개).
  - `[깔아줌]` = 학습 대상이 아닌 잡일(설치·설정·보일러플레이트). 코치가 그냥 해준다.
  - `[복습]` = 안 보고 떠올리기 → 확인 → 직접 적용 → 한 줄 설명.
- 막히면 15분 룰: 같은 에러로 15분 넘기면 힌트 단계로 넘어가거나 질문한다.
- 완료 기준은 "완벽"이 아니라 **"작동하는가 + 내 말로 30초 설명 가능한가"**.

### 데이터 규칙 요약 (검수 기준 — 계속 참고)
- CSV 컬럼: `expense_id, employee, department, category, amount, date, vendor, reason, has_receipt`
- 영수증 누락: `has_receipt == 'N'`
- 식대 한도: `category == 식대` 이고 `amount > 20,000`
- 야근식대 한도: `category == 야근식대` 이고 `amount > 15,000`
- 택시비 사유 부족: `category == 택시비` 이고 `amount > 30,000` 이고 `reason` 비어있음
- 사무용품 추가승인: `category == 사무용품` 이고 `amount > 100,000`
- 중복 신청: `employee + date + amount + vendor` 동일
- 이상 비용 후보: 같은 `category` 평균의 **2배 이상**
- 결과 컬럼: `risk_type, risk_reason, policy_evidence, suggested_action, draft_message, review_status`

# Week 1 — CSV 검수기

## Day 1 — 환경 + 첫 화면 + CSV 업로드
### 오늘의 목표
CSV를 올리면 표로 보여주는 Streamlit 화면 하나를 띄운다.
### 할 일 (세션 4개)
1. `[깔아줌]` (25분) 가상환경 + `streamlit`, `pandas` 설치, `requirements.txt`, 빈 `app.py` 생성 — *"이건 배울 대상이 아니라 그냥 깔아주는 부분이야."*
2. `[직접]` (30분) `app.py`에 제목 + "Hello" 한 줄 → `streamlit run app.py`로 실행해서 브라우저에 뜨는지 확인.
3. `[직접]` (35분) `st.file_uploader`로 CSV 받기 → `pd.read_csv` → `st.dataframe`으로 표 출력.
4. `[직접]` (30분) `sample_expenses.csv`를 손으로 12~15행 만든다 (위 컬럼/규칙에 걸릴 케이스 몇 개 섞기).
### 오늘 배우는 개념 (3개)
- Streamlit이 뭐고 왜 쓰나 (파이썬만으로 웹 화면).
- `st.file_uploader` / `st.dataframe` 기본.
- `pd.read_csv`로 CSV → 표(DataFrame).
### 완료 기준
브라우저에서 CSV 업로드 → 표가 뜬다.
### 막혔을 때 최소선
업로드까지 안 되면, 일단 `pd.read_csv("sample_expenses.csv")` 고정 경로로 표만 띄워도 성공.
### 30초 설명
"파이썬 Streamlit으로 CSV를 업로드하면 바로 표로 보여주는 화면을 만들었습니다."

## Day 2 — 데이터 요약
### 오늘의 목표
업로드한 데이터의 건수·컬럼·결측치·총액을 화면에 요약한다.
### 할 일
1. `[직접]` (30분) 행/열 개수(`df.shape`), 컬럼 목록(`df.columns`) 표시.
2. `[직접]` (30분) 결측치 개수(`df.isna().sum()`) 표시.
3. `[직접]` (35분) 총 신청 금액(`amount.sum()`) + 카테고리별 합계(`groupby("category")["amount"].sum()`).
4. `[복습]` (25분) 오늘 개념 3개 안 보고 설명 → 요약 코드 한 조각 안 보고 다시 치기.
### 오늘 배우는 개념 (3개)
- `df.shape / df.columns` (데이터 크기·구조).
- `isna().sum()` (결측치).
- `groupby().sum()` (집계).
### 완료 기준
업로드하면 건수·총액·결측치·카테고리별 합계가 화면에 뜬다.
### 막혔을 때 최소선
`groupby`가 어려우면 총액·건수·결측치까지만 해도 성공.
### 30초 설명
"업로드된 비용 데이터의 규모와 결측 상태, 항목별 금액을 자동 요약해 데이터 품질을 먼저 확인합니다."

## Day 3 — 위험 탐지 규칙 ①(영수증·한도)
### 오늘의 목표
영수증 누락과 식대/야근식대 한도 초과 건을 자동으로 골라낸다.
### 할 일
1. `[개념]` (25분) boolean indexing(조건 필터) 최소개념 — `df[df["amount"] > 20000]` 예시.
2. `[직접]` (35분) 영수증 누락: `has_receipt == 'N'` 건 표시.
3. `[직접]` (35분) 식대 > 20,000 / 야근식대 > 15,000 한도 초과 탐지.
4. `[직접]` (30분) 걸린 건에 `risk_type`, `risk_reason` 컬럼 채우기.
### 오늘 배우는 개념 (3개)
- 조건 필터(boolean indexing).
- 여러 조건 결합 (`&`, 괄호 주의).
- 새 컬럼에 값 넣기 (`df.loc[조건, "risk_type"] = ...`).
### 완료 기준
영수증 누락 + 한도 초과 건에 위험 유형/사유가 붙는다.
### 막혔을 때 최소선
영수증 누락 한 가지만 정확히 골라내도 성공. 나머지는 내일 이어서.
### 30초 설명
"규정 기준(영수증 여부·항목별 한도)을 코드로 옮겨, 검수가 필요한 건을 자동으로 표시합니다."

## Day 4 — 위험 탐지 규칙 ②(택시·사무용품·함수 분리)
### 오늘의 목표
나머지 규칙을 추가하고, 규칙들을 함수로 깔끔히 분리한다.
### 할 일
1. `[직접]` (35분) 택시비 > 30,000 이고 `reason` 비어있으면 "사유 부족".
2. `[직접]` (30분) 사무용품 > 100,000 이면 "추가 승인 필요".
3. `[직접]` (40분) 규칙들을 `src/audit_rules.py`의 함수로 분리하고 `app.py`에서 호출.
4. `[복습]` (25분) Week1 중간 회고 + 규칙 함수 1개 안 보고 다시 구현.
### 오늘 배우는 개념 (3개)
- 문자열/빈값 조건 (`reason` 결측 판단).
- 함수로 로직 분리 (`def detect_xxx(df):`).
- import로 다른 파일 함수 쓰기.
### 완료 기준
5가지 규칙(영수증·식대·야근식대·택시·사무용품)이 함수로 동작한다.
### 막혔을 때 최소선
함수 분리가 부담되면 `app.py` 안에 그대로 둬도 됨. 규칙 동작이 우선.
### 30초 설명
"검수 규칙을 함수 단위로 분리해, 규칙을 추가·수정하기 쉬운 구조로 만들었습니다."

## Day 5 — 중복/이상 탐지 + Week1 마무리
### 오늘의 목표
중복 신청과 이상 비용 후보까지 탐지하고 1주차 흐름을 닫는다.
### 할 일
1. `[개념]` (25분) `duplicated`, 그룹 평균 비교 최소개념.
2. `[직접]` (35분) 중복 신청: `employee+date+amount+vendor` 동일 건.
3. `[직접]` (35분) 이상 비용 후보: 카테고리 평균의 2배 이상.
4. `[복습]` (30분) Week1 전체 흐름 30초 설명 + 실행 화면 캡처 1장.
### 오늘 배우는 개념 (3개)

- 그룹 평균 (`groupby.transform("mean")` 개념).

7종 위험 유형이 모두 탐지되고, CSV 업로드→위험 건 표시가 한 번에 흐른다.

### 30초 설명

# Week 2 — 미니 RAG + 보완 요청 초안

## Day 6 — policy.txt 작성 + 문단 분리
### 오늘의 목표
비용 규정 문서를 만들고, 코드로 섹션 단위 조각(chunk)으로 나눈다.
### 할 일
1. `[깔아줌+직접]` (30분) `policy.txt` 규정 문서 초안 — 항목별 한도/영수증/중복 규정을 섹션으로. (내용은 같이 잡아줌)
2. `[개념]` (25분) RAG가 뭔지·왜 쓰는지 초보 눈높이로 (문서에서 근거 찾아 붙이기).
3. `[직접]` (35분) `policy.txt` 읽어서 섹션 구분자로 split → 문단 리스트.
4. `[직접]` (30분) 각 조각을 `{title, text}` 형태로 정리 (`src/policy_retriever.py` 시작).
### 오늘 배우는 개념 (3개)
- 파일 읽기 (`open().read()`).
- 문자열 split / 리스트 다루기.
- chunk(문서 조각)의 개념.
### 완료 기준
policy.txt가 여러 개의 규정 조각 리스트로 나뉜다.
### 막혔을 때 최소선
자동 split이 어렵면, 조각 리스트를 손으로 몇 개 만들어 두고 진행.
### 30초 설명
"규정 문서를 조각으로 나눠, 위험 건에 맞는 근거를 찾을 수 있게 준비했습니다."

## Day 7 — 규정 근거 검색
### 오늘의 목표
위험 유형/항목에 맞는 규정 조각을 찾아 근거로 붙인다.
### 할 일
1. `[개념]` (25분) 키워드 매칭 검색 원리 (임베딩 없이 규칙/키워드로).
2. `[직접]` (35분) `risk_type`/`category` → 검색 키워드 매핑 표 만들기.
3. `[직접]` (35분) 매핑 키워드로 관련 조각 찾아 `policy_evidence` 반환.
4. `[복습]` (25분) 근거 못 찾으면 "관련 규정 확인 필요"로 처리(환각 방지).
### 오늘 배우는 개념 (3개)
- dict(매핑 테이블).
- 문자열 포함 검색 (`in`).
- 실패 케이스 기본값 처리.
### 완료 기준

### 30초 설명

## Day 8 — 검색 튜닝 + 검수 결과 결합
### 오늘의 목표
위험 건 표에 규정 근거를 합치고, 화면에 함께 보여준다.
### 할 일
1. `[직접]` (35분) 위험 건 DataFrame에 `policy_evidence` 컬럼 결합.
2. `[직접]` (30분) 매칭 실패 케이스 골라내 매핑 보강.
3. `[직접]` (35분) Streamlit에 "위험 건 + 사유 + 근거" 한 테이블로 표시.
4. `[복습]` (25분) 검색 흐름(입력→매핑→근거) 안 보고 설명.
### 오늘 배우는 개념 (3개)
- 컬럼 합치기/맵 적용 (`apply`).
- 매칭률 눈으로 확인.
