# 05 · 독립 평가 vs 회귀 테스트 구분 (DAY1 B08)

> 기록일: 2026-11-07 (KST) · 11.08 계획 B08 + 10.17 "업무 규칙 검증"

## 두 가지는 다른 것이다 (★포트폴리오 정직성 핵심)

| | 1,000건 회귀 테스트 | 독립 평가 (신규) |
|---|---|---|
| 파일 | `sample_expenses_1000.csv` + `tests/data/expected_risks_1000.csv` | `tests/data/independent_cases.csv` + `independent_expected.csv` |
| 정답(expected) 출처 | **`detect_risks()` 출력을 그대로 저장** (`scripts/save_expected_risks.py`) | **사람이 규정 임계값을 보고 직접 정의** |
| 측정하는 것 | "코드를 고쳐도 출력이 **예전과 같은가**(회귀)" | "코드가 **규정 스펙대로 맞는가**(정확도)" |
| 통과의 의미 | 안 깨졌다 | 스펙과 일치한다 |
| 주의 | 규칙에 버그가 있으면 정답에도 같은 버그 → **"정확도 100%"라고 부르면 안 됨** | 소표본·규정기준이라 "실사용 정확도"와는 다름 |

## 독립 평가 결과 (실측)

```
실행: PYTHONPATH=. python scripts/evaluate_risks.py

표본: 12건 (expense_id x risk_type 단위)
TP=10  FP=0  FN=0
Precision = 1.000
Recall    = 1.000
F1        = 1.000
→ 이 소표본·규정 임계값 기준으로 모든 케이스 일치
```

### 평가셋이 덮는 조건
- 경계값: 식대 20000 vs 20001 / 소모품 49999 vs 50000 / 교통 15000 vs 15001
- 영수증 Y vs N
- 복수 위험: 식대 35000+영수증N(2개), 교통 30001+사유없음(2개)
- 중복 신청(동일 employee/date/amount/vendor 2건, 배치 문맥 유지)
- 정상(위험 0) 케이스 4건
- 평가 단위: `expense_id × risk_type` 쌍으로 TP/FP/FN 집계

## 한계 (정직 표기)
- **표본 12건**으로 작다 — "전반적 정확도"가 아니라 "규정 경계값에서 코드가 스펙을 지키는지" 확인용.
- expected는 규정 임계값 기반 수기 정의 — 실제 회사 라벨링 데이터가 아님(합성).
- `이상 비용 후보`(카테고리 평균 2배) 규칙은 배치 구성에 따라 값이 바뀌어 이 소표본에선 의도적으로 미발화되게 설계 → 별도 평가 대상.
- 참고: `tests/data/synthetic_audit_cases.csv`, `expected_risks.csv`는 현재 **빈 파일**(10.17 잔재) → B09 정리 대상.

## 30초 설명
> "1,000건 테스트는 코드 출력을 정답으로 삼은 **회귀 테스트**라 '안 깨졌다'는 뜻이지 정확도가 아니다.
> 그래서 규정 임계값을 보고 사람이 정답을 매긴 **독립 평가셋 12건**을 따로 만들어 경계값에서
> Precision/Recall/F1을 쟀고, 이 소표본에선 모두 일치했다. 둘을 섞어 '정확도 100%'라고 말하지 않는다."
