## Q1. Gemini를 쓰고 싶은데 왜 코드는 `OpenAI()`를 그대로 썼나요?

**A.** 구글이 "우리 Gemini도 OpenAI랑 **똑같은 방식**으로 부를 수 있게 문을 열어줄게" 하고 만든 통로가 있어서 그래. 이걸 **OpenAI 호환(compatible) 엔드포인트**라고 해.

그래서 코드 전체를 바꿀 필요 없이, **전화 거는 주소(base_url)와 열쇠(api_key)만 구글 걸로** 바꾸면 됨.

```python
client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),   # .env에 든 Gemini 키
    base_url="https://generativelanguage.googleapis.com/v1beta/openai/",  # 구글 주소
)
```
> 한 줄 정리: 같은 "말투(OpenAI SDK)"로 다른 "회사(구글 서버)"에 전화 거는 것.

## Q2. `401 AuthenticationError`가 나요. 키가 OpenAI 건지 Gemini 건지 어떻게 구분하나요?

**A.** 401은 "**열쇠가 안 맞아서 문 앞에서 쫓겨남**"이라는 뜻이야. 보통 키 모양으로 어느 회사 건지 짐작할 수 있어:

| 키 시작 모양 | 어느 회사 |
|---|---|
| `sk-...` | OpenAI |
| `AQ.Ab8...` 등 | 구글(Gemini) |

→ 구글 키를 들고 OpenAI 서버(기본 주소)로 전화하면 "너 우리 회원 아니야" 하고 401. 키에 맞는 주소(base_url)로 걸어야 함.

## Q3. 키가 분명 `.env`에 있는데 "api_key가 없다"는 에러가 나요.

**A.** `os.getenv("이름")`은 `.env`에 적힌 **이름을 글자 그대로** 찾아. 이름이 한 글자라도 다르면 값이 있어도 **None(빈 값)** 을 돌려줘.

- 내 실수: `.env`엔 `OPENAI_API_KEY=...`로 저장돼 있는데, 코드에선 `os.getenv("GOOGLE_API_KEY")`로 찾음 → 이름 불일치 → None → "키 없음" 에러.
- 해결: `.env`의 `=` 왼쪽 이름과 `getenv("...")` 안의 이름을 **똑같이** 맞추기.

> 핵심: 값이 아니라 **이름(라벨)** 이 안 맞으면 못 찾는다.

## Q4. `404 NotFoundError`는 왜 났나요? (OpenAI API 두 가지 모양)

**A.** 404는 "**그 주소(문)에 그런 게 없어**"라는 뜻. OpenAI 호출 방식엔 2가지 모양이 있는데, Gemini 호환 통로는 그중 하나만 열어놨어.

| | Responses API (최신) | Chat Completions API (표준) |
|---|---|---|
| 호출 | `client.responses.create` | `client.chat.completions.create` |
| 입력 | `input="..."` | `messages=[{"role":"user","content":"..."}]` |
| 출력 꺼내기 | `response.output_text` | `response.choices[0].message.content` |

→ Gemini는 **`chat.completions`만** 지원해서, `responses`로 부르니 "그런 문 없음(404)". 오른쪽 방식으로 바꾸니 해결.

## Q5. 응답 한글이 터미널에서 `��ö��`처럼 깨져요. 코드가 잘못된 건가요?

**A.** 아니야, **코드 문제 아님.** 실제 데이터(JSON 응답)는 정상 한글(UTF-8)인데, **윈도우 터미널의 글자 표시 방식(cp949)** 때문에 화면에만 깨져 보이는 거야.

- 확인법: 브라우저 `/docs`나 실제 저장된 값으로 보면 멀쩡함.
- 즉 "**눈에 보이는 깨짐 ≠ 데이터 깨짐**". 터미널 출력일 땐 당황하지 말 것.
