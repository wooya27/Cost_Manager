## B17 · 기술 질문 10개 (답안 초안)

**1. 왜 식대/영수증 판단은 LLM이 아니라 규칙 기반인가?**
금액 한도·영수증 유무는 정답이 명확한 결정론적 판단이라, 규칙으로 하면 같은 입력에 항상 같은 결과가 나와 재현·설명·테스트가 쉽다. LLM은 비결정적이라 판정에 쓰면 근거 없이 흔들린다. 그래서 판정은 규칙, LLM은 문장 생성에만 썼다.

**2. FastAPI의 Pydantic 검증은 무엇을 막나? (422)**
요청이 로직에 닿기 전에 타입·필수 필드를 걸러준다. 예를 들어 `amount`에 문자열이 오면 422로 거부돼 잘못된 데이터가 DB·AI로 흘러가지 않는다.

**3. 단건 `/audit`과 `/audit/batch` 차이는?**
단건은 탐지+RAG+LLM+DB 저장까지 전체를 돈다. 배치는 중복·평균 이상치처럼 여러 행이 있어야 되는 규칙을 "탐지"만 한다(RAG·LLM·DB 안 함). 그래서 "배치가 N건 탐지"를 "N건 AI 처리"로 말하면 안 된다.

**4. 일반 컬럼과 JSONB를 함께 쓰는 이유는?**
한 비용에 위험이 여러 개라 `risks`는 가변 리스트 → JSONB로 통째 저장. 조회·검수에 자주 쓰는 대표값(employee, 대표 risk_type, review_status)은 일반 컬럼으로 두어 질의가 쉽다.

**5. Embedding·pgVector·Top-K 검색 과정은?**
규정을 조각내 임베딩(숫자 벡터)으로 만들어 pgVector에 저장. 위험 사유도 임베딩해서 코사인 거리(`<=>`)로 가장 가까운 규정 Top-3를 가져온다.

**6. Hit@3 98.8%와 실제 운영 정확도가 왜 다른가?**
Hit@3은 "검색 결과 상위 3개 안에 정답 규정이 있나"는 **검색 지표**이고, 평가 질의가 **자동 생성**이라 실사용 질의와 다르다. 업무 전체 정확도가 아니라 검색 단계 성능일 뿐이다.

**7. Human-in-the-loop은 어디에 실제 반영됐나?**
AI 결과를 바로 확정하지 않고 `unreviewed`로 DB에 저장한 뒤, 담당자가 `PATCH /audit-results/{id}/review`로 approved/need_revision/rejected를 정한다. 화면 문구가 아니라 상태 변경 기능으로 증명된다.

**8. 근거 없음 / LLM 실패 / DB 실패는 어떻게 다르게 처리하나?**
근거 없음 = 정상 업무 분기 → LLM 호출 안 하고 `needs_review`로 사람에게. LLM 실패 = 템플릿 fallback으로 업무 지속. DB 실패 = 시스템 장애 → 가짜 성공 id 안 주고 500으로 실패를 드러낸다.

**9. LangGraph와 n8n의 역할 차이는?**
LangGraph는 앱 내부 처리의 상태·조건분기·실패경로를 관리하는 구현. n8n은 Google Sheets 같은 외부 도구와 API를 잇는 오케스트레이션. (현재 LangGraph는 독립 구현이고 API 실연결은 다음 단계라고 정직히 말함.)

**10. pytest/CI 통과와 DB·RAG 통합 테스트 통과는 왜 다른가?**
CI는 외부 의존 없는 비통합 테스트(`-m "not integration"`)만 돌린다. DB·임베딩이 필요한 통합 테스트는 환경이 있어야 돌아가므로, CI 초록이 전체 통합 동작을 보장하지는 않는다.

> 보너스(회귀 vs 정확도): "1,000건은 코드 출력을 정답으로 삼은 회귀 테스트라 안 깨짐을 보장할 뿐, 규정 기준 정확도는 사람이 정답을 매긴 독립 12건으로 따로 쟀다."

## B18 · 회사별 20초 연결 멘트

- **아정네트웍스 / 케이솔루션즈 / 이지태스크 (업무 자동화·승인):**
  "반복 검수를 API로 자동화하고, 규정이 바뀌어도 규칙·규정 데이터만 갱신하면 되는 구조로 만들었습니다. 승인 흐름은 사람이 최종 판단하도록 분리했습니다."
- **인젠트 / 씨엠월드 (DB·데이터 설계):**
  "PostgreSQL 일반 컬럼과 JSONB를 함께 써서 가변 위험 데이터를 저장하고, POST→GET→PATCH로 상태를 관리했습니다. 고객사 데이터 구조에 맞춰 확장 가능합니다."
- **SWM / 린솔 (RAG·LLM 통제):**
  "RAG 검색 성능을 Hit@K로 평가하되 자동생성 질의라는 한계를 구분했고, 근거가 없으면 LLM을 호출하지 않아 환각을 막는 안전장치를 넣었습니다."
- **틸론 / 유호스트 (컨테이너·운영):**
  "Dockerfile·compose로 재현 가능하게 만들고, 실패 경로(재시도·fallback·500)와 run_id 로깅으로 장애 위치를 추적할 수 있게 했습니다."
- **KX넥스지 / 노츠 (QA·보안 인식):**
  "경계값·실패 케이스를 pytest로 검증하고, 인증/권한은 아직 미구현임을 정직하게 구분해 말씀드립니다. 잘못된 입력은 422, 없는 자원은 404로 방어합니다."
